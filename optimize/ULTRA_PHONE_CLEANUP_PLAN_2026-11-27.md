# ULTRA PHONE: two independent cleanup modes
1. Daily cleanup: one action, Android background-only `am kill` on explicit nonessential packages, no force-stop, data deletion, caches or package-state changes. Show measured MemAvailable before/after and remaining processes. Android app UI/one-touch shortcut requires a legitimate shell bridge; no root or permission bypass.
2. Dedicated server mode: explicit allowlist (Instagram, ChatGPT, Letgo, WPS, entertainment/social apps etc.), reversible third-party package disable only after per-user, shared UID, admin and managed-profile checks. Preserve original states, durable journal, crash recovery. Google Search/Gboard remain installed and enabled; only safe background kill if not active; preserve fallback input, SurfaceFlinger, launcher, phone, system UI, network, security, thermal, accessibility and power services. Never touch user 999 without separate profile-specific verification; do not bypass Android policy. No blanket force-stop or CPU scheduler/thermal override.
3. Integrate server lifecycle after isolated test: prepare/enter, JVM launch with bounded heap and available memory reservation, graceful stop, restore and verify; no live server modifications. Measure before/after and under load; 8 GiB available is aspirational not promised. No downloads.
4. Validate offline local tooling; dry-run on actual phone, safe daily sweep, then verify state and test server policy in simulation before actual enter/leave. Keep mobile app/shortcut and server integration status distinct.
